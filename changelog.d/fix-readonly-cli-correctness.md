### Fixed

- **The read-only operator commands can no longer write to your database.** `ovumcy export`, `summary`, `trends` and `predict` used to open the SQLite database read-write and run the embedded migrations first, so running one against a live instance could create `-wal`/`-shm` files and rewrite the server's data file. They now open it read-only and migrate nothing; a mistyped `DB_PATH` fails instead of producing an empty database.
- **`--id 0` is refused instead of addressing a different account.** All four reporting commands treated a zero `--id` as "no id given" and fell through to the email argument, so `ovumcy export --id 0 owner@example.com` exported whichever account the email named. An `--id` that is not a positive number is now an error naming the value.
- **`summary`, `trends` and `predict` resolve "today" in the owner's timezone.** Anchored on UTC, an owner in `America/Chicago` was a day off every evening after 18:00 CST — the summary window ended on a calendar day they had not reached and the projection stepped from yesterday. They now use the account's stored timezone (falling back to `UTC`), and `summary` gains the `--tz` override the other two already had.
- **`ovumcy export --out` always ends up `0600`, and stdout failures are reported.** Overwriting an existing file kept that file's wider mode — a second export onto a `0644` path published intimate health data world-readable. The mode is now enforced on the open file, and a failed stdout write (closed pipe, full disk) exits non-zero instead of reporting success on a truncated document.
