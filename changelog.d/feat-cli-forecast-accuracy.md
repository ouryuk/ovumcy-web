### Added

- **`ovumcy forecast-accuracy` scores the prediction against its own history.** `ovumcy predict` answers "when is the next cycle", but nothing answered "how well is that answer holding up?" — an operator had no way to see the model's historical accuracy from the shell. The new read-only CLI subcommand (`ovumcy forecast-accuracy <email> [--id <id>] [--tz <IANA name>] [--json]`) walks the owner's completed cycles in order and, for each one, recomputes the projection the model WOULD have made from only the cycles before it — the same `BuildCycleStatsFromLogs` derivation the dashboard uses, run at an explicit past "as of" date, so the check is deterministic and clock-free — then reports the signed per-cycle error in days, whether the actual start fell inside the model's own recent length range, and a summary (mean and median absolute error, worst cycle, within-window count and percentage) as a table or a versioned `ovumcy-forecast-accuracy/v1` JSON document. Cycles the model would not have predicted at all (pregnancy pause, too little history) are reported as skipped with a reason, never scored as zero error. Nothing is written and no secret is read, exactly like `export`, `summary`, `trends` and `predict`.
